# i18n Skill

Use when adding a language, translating new strings, or working with text on canvas vs in React.

## Where Strings Live

- **`src/locales/<code>.json`** — UI strings (menus, modals, HUD labels)
- **Character pack `translations` field** — per-character display names (in `src/engine/characters/packs/*.ts`)
- **Arena pack `translations` field** — per-arena display names (in `src/engine/arenas/packs/*.ts`)

Arena and character names live in their packs, NOT in locale JSON.

## React vs Canvas

- **React components**: use the `useTranslation()` hook normally
- **Canvas drawing code**: call `i18n.t()` directly (not the hook). The hook only works inside a component tree

## Default Language

Czech (`cs`) is the default; English (`en`) is the fallback. Persisted in `carrotroyale_lang` via `safeStorage` (do NOT inline `localStorage`).

Tests force `i18n.changeLanguage('en')` so string assertions work regardless of default.

## Adding a New Language

1. Create `src/locales/<code>.json` — copy `en.json`, translate all keys. Verify key count matches with a script.
2. Import in `src/i18n.ts`, add to `resources` object.
3. Add to the `languages` array in `MainMenu.tsx` lang-toggle (data-driven `.map()` loop — code, label, flag SVG).
4. Add `<code>` key to `translations` in:
   - All 17 character packs in `src/engine/characters/packs/`
   - All 11 arena packs in `src/engine/arenas/packs/`

## Translation Style Rules

- **Arena names must fit the selector boxes** — test at runtime, shorten long names.
- **Avoid literal translations** — use natural/colloquial phrasing. Gaming terms (gravity, stomp, kills) often stay in English or use loan words. Academic translations (गुरुत्वाकर्षण, भौतिकी, pisika) sound wrong in a game UI.
- **Czech `cs` is the default** — write the cs translation first, English second; that order surfaces awkward phrasings sooner.
