# Engine Caveats

## Debug Flags
- **`debugFlags.ts` runtime toggles**: `setDebugFlag(name, value)` / `getDebugFlag(name)` (used by DevMenu) flip both `*Allowed` and `*Enabled` together — bypasses URL gating. The older `toggleNavDebug/toggleNetDebug/toggleFpsDebug` only flip `*Enabled` and require `*Allowed=true` (set by `?debug=`). New runtime UI should prefer `setDebugFlag`; reserve the URL path for E2E and launch-flag use. The in-match backtick handler in `GameLoop` still uses `toggle*Debug` (cycles all currently-allowed flags).

## Renderer & Sprites
- Sprite drawing dispatches via `getSpriteRenderer(name)` / `getGibRenderer(name)` from character pack registry. Fallback pill-shape for unknown characters.
- Idle actions: shared library in `rendering/idleActions.ts` (6 actions: `headBob`, `headTilt`, `headShake`, `littleHop`, `stretch`, `lookAround`) + per-pack `CharacterPack.idleActions` config (`weights` overrides + `custom` signatures). State machine helper `tickIdleStateMachine(player, dt)` is called from both `playerCosmetics.ts` (in-match) and `lobbyGame.ts` (lobby): 0.8s first-action delay, then alternating 0.6–1.4s rest gap and ~0.7–1.0s actions. State (`idleAction`, `idleActionTimer`, `idleActionDuration`) is local-only — NOT in `net/snapshot.ts`. Each peer rolls actions independently; cosmetic divergence is acceptable. Action ctx transform is applied to the main canvas around `drawImage(cached, ...)`, NOT inside `_drawCharacterSpriteImpl` — otherwise the per-frame transform bakes into the 1-bit-keyed sprite cache and the action freezes. The transform path is gated on `idleAnimAction != null` so non-idle players skip allocation + save/restore on every render frame. Per-pack in-sprite tweaks (bunny ear-twitch, bear scratch, fox tail-wag, frog blink) still ride on the cached sprite via `isIdleAnim`/`idleT` params; they live with the 1-bit cache granularity.
- `spriteShading.ts`: `fillBodyGradient` for body fill, `drawHighlightSpot` for glint. Gradient edge blended 30% toward `darkColor` (not raw) to avoid harsh contrast on Panda/Cow.
- At 40px character height, subtle effects become prominent. Highlight spots must be ≤0.18 alpha. Stipple dots and outer glows look bad.
- Bubble helmet drawn at end of `drawCharacterSprite` for `space_station` and `underwater` themes only.
- Always-on character outline: `darken(char.color, 0.8)` baked into the sprite cache via `applyOutlineToCache` (4-offset silhouette stamp, `destination-over`). The cache canvas already carries a `_spriteScale` transform from the original draw — outline stamps and ctx filters need `setTransform(1,0,0,1,0,0)` first or offsets get scaled twice.
- Cache boundary for cosmetics: effects that SHOULD be outlined (body, eyes, legs, helmet) draw inside `_drawCharacterSpriteImpl`. Effects that should NOT (motion lines, fast-fall lines, expressions, blush, fire glow) draw in `drawPlayer` after the cache blit.
- `pack.darkColor` is the body-shading base, NOT a generic "darker version of color" — for high-contrast packs (Tiger stripes, Panda patches) it's the near-black spot color and reads as a heavy black rim if reused. To derive a moderate darker shade for outlines/effects, multiply `pack.color` via `darken(hex, factor)` in `rendering/players.ts`.
- `hexToRGB(hex) → {r,g,b}` in `fastMath.ts` is the canonical hex parser — don't inline `parseInt(hex.slice(...))`. House style: emit parsed colors as `rgb(r,g,b)` strings (see `spriteShading.ts`, `renderer.ts`). Three darken helpers exist (`players.ts`, `underwater.ts`, `navDebugOverlay.ts`); fold into a shared util when adding a fourth.
- Day/night rendering must check `this.theme.dayNight.enabled` before drawing. "Remove day/night" also means hide sun/moon from `drawFarBackground`.

## Render Scale
- Backing store grows to `1280×720 × min(devicePixelRatio, 2)` on desktop; touch stays at 1×. Use `applyRenderScaleToCanvas(canvas, ctx, scale)` from `renderScale.ts` — never set `canvas.width/height` directly.
- **Setting `canvas.width` resets the ctx transform AND the canvas's intrinsic layout size.** The helper does both: re-applies `setTransform(s,0,0,s,0,0)` and pins `canvas.style.width/height` to logical dims (otherwise the canvas overflows its parent — see "completely broken, zoomed in").
- Sprite cache (`players.ts`) and HUD cache (`hud.ts`) backing stores include scale; both expose `setSpriteCacheScale()` / `setHudScale()` which clear the cache on change. Sprite cache cap shrinks quadratically with scale to bound memory.
- `matchMedia('(resolution: Xdppx)')` only fires the transition AWAY from X — `renderScale.ts` re-creates the listener on each change.
- `Renderer.setRenderScale()` re-runs `renderBackground()` with the cached arena. Baked gibs/blood drips on the bg canvas are lost on scale change (rare event).

## Local-Device Preferences vs Match Mods
- **Match mods** (`matchSettings.mods.*`): host-authoritative, synced to guests via `SETTINGS_SYNC`, persisted in `gameStore` localStorage. Add via `MOD_LIST` in `ModsModal.tsx`.
- **Local-device prefs**: never synced to peers. Pattern: `createEmitter<T>()` from `engine/emitter.ts` for the listener glue, `safeStorage` from `src/storage.ts` for persistence. See `perfFlags.ts` (simple) and `characters/preferences.ts` (with derived cache). React subscribes via `useSyncExternalStore(subscribe, get)` with hoisted callbacks — never `useState(getX())` (stale snapshot).

## Game Loop
- **System architecture**: GameLoop owns two system arrays (`GameplaySystem[]` for `fixedUpdate`, `CosmeticSystem[]` for `cosmeticStep`). Each system implements `init(state) / update(dt) / cleanup()`. Systems receive shared state via constructor and call pure functions from the `cosmetics/` and `gameplay/` subdirectories.
- **ParticleSystem** is the central VFX hub — other systems reference it for `emitParticle()`, `spawnKillSplatter()`, `applyHazardHitVFX()`, etc. Created first in GameLoop constructor.
- **Per-player systems** (EffectZoneSystem, PlayerCollisionSystem) have `applyToPlayer()`/`checkCollisions()` methods called from GameLoop's per-player loop, NOT from the system array iteration.
- **`erasableSyntaxOnly: true`** in tsconfig — cannot use constructor parameter properties (`private foo: T` in constructor). Use explicit field declarations + constructor body assignment.
- **`DEFAULT_*` constants use plain `const X: Readonly<T> = {...}`**, not `Object.freeze({...})`. `Readonly` already enforces immutability at the type level; the runtime freeze adds nothing for an internal config object. Engine-wide convention — see `headless/HeadlessRunner.ts:DEFAULT_MAX_TICKS`, `net/core/networkSimulator.ts:DEFAULT_CONFIG`, `ai/personality.ts:DEFAULT_PERSONALITY`, `headless/reward.ts:DEFAULT_REWARD_WEIGHTS`.
- **Avoid `.bind(this)` in hot paths** — creates new function per call. Use cached arrow fields: `private readonly _boundFn = (): T => this.fn()`.
- **`audio.playAnimal(name)`** is separate from `audio.play(name)` — both must be gated by `_audioEnabled` for rollback resimulation. Route through callbacks, not direct imports.
- `fixedUpdate` returns early when `matchOver` — timers that should keep running (screenFlash, slowMotion, hitstopZoom) must be decayed in `loop()` instead. **`screenShake` is the exception**: it decays inside `fixedUpdate` (`Simulator.ts:356`, gated by `!_resimulating`), so it freezes both after `matchOver` and during pause. Zero it at the source on those transitions (matchOver latch in `Simulator.ts`, `GameLoop.pause()`) — don't add render-side guards.
- Stomps must be checked BEFORE `collidePlayersHorizontal`; collision skips when vertical overlap < 50% (stomp zone).
- Never splice/shift `splatMarks` during `fixedUpdate` — multiple ticks per frame + `newSplatsSinceRender` stores indices. Cap array in render path only.
- `GameLoop.stop()` must stop ALL looping sounds — music, ambient, wind, zero_g, crowd, plus all theme `activeAmbientLoops`.
- Entity cleanup uses `swapRemove(arr, i)` in reverse-iterate loops. O(1), no order. Never `.filter()` per frame.
- New particles: always use `particleSystem.emitParticle()`, never push to the array directly.
- **`MatchState.phase`**: `'loading' | 'playing' | 'over'`. Default `'loading'` in `createInitialMatchState()`. `fixedUpdate` AND `cosmeticStep` both early-return during `'loading'`. Production transitions: `setPhase('playing')` in GameLoop (fires arena music + ambient + matchSystem.init on first entry); `setPhase` is also called by the NetMatch host-side LOADED handshake. `setOnPhaseChange(cb)` subscribes to transitions — used by Match.tsx to toggle the loading overlay. Test helpers default to `'playing'`; `createLoop` helpers that instantiate a real GameLoop must flip `state.phase = 'playing'` after construction (or use the public setPhase) to run pre-existing physics tests.
- **Arena change mid-match**: use `gameLoop.switchArena(arenaId, overrides?)` — does in-place arena swap (scores reset, state re-initialized via `createInitialMatchState`, all arena-dependent systems reconstructed, renderer theme swapped). Flips phase back to `'loading'`. Match.tsx's `handleChangeArena` must NOT put `currentArenaId` in the useEffect dep array — that triggers a component remount which drops NetMatch transport wiring.
- **Match-end auto-guard**: `MatchSystem.fixedUpdate` ends the match if only one human remains with no bots (that human wins), or if all players are disconnected (null winner). Prevents online host from playing forever against disconnected opponents.
- **Spring-vs-input-jump cosmetic signal**: rising edge of `Player.springTrailTimer` (`prev === 0 && curr > 0`). Already snapshotted, works on host + guest. There is NO equivalent for geyser launches — `JUMP_IMPULSE = -560` and geyser strength `-550` are indistinguishable via `prev.vy - player.vy` thresholds (the old `> 300` heuristic fired on every normal jump and was removed). Restoring geyser-specific cosmetics needs a per-player `geyserLaunchTimer` field with snapshot wire-format change + `PROTOCOL_VERSION` bump.
- **`SpringMushroom.bounceTimer` is NOT a `Player` field** — it's the spring-entity's own contact cooldown. For player-side spring detection use `springTrailTimer`.
- **Extending `PrevPlayerCosmeticState`** requires updating three locations in `playerTransitions.ts`: the interface, `snapshotPlayerCosmeticState()`, AND the prev-state-update block at the end of `detectPlayerTransitions()`. Missing one location leaves the prev field at its initial value, creating a stale-zero bug invisible to typecheck.
- **`fastFalling` stays true on upward bounces.** Spring, geyser, bouncy platform, and stomp all reverse `vy` without clearing the boolean — physics needs it set (down still held + airborne) for `FAST_FALL_GRAVITY`. Cosmetic code wanting "actively diving" must gate on `fastFalling && vy >= 0`, not the boolean alone.
- **Cosmetic transition anchors use NaN-sentinel.** "Frozen position at a moment" fields (`springLaunchX/Y`, `fastFallAnchorX/Y`) default to `NaN` in all init sites (`simulator/initialState.ts`, `__tests__/testHelpers.ts`, `lobbyGame.ts`, `net.test.ts`) and gate with `Number.isFinite()`. `0` is a reachable coord, so `> 0` fallbacks misfire at the seam. Test fixtures using `as unknown as Player` casts must set the field explicitly — `undefined` short-circuits the renderer's `isFinite` check.
- **Capture transition anchors in fixedUpdate or the renderer, NOT cosmeticStep.** `cosmeticStep` runs at half-rate (~30Hz via `tickCosmetic`), so capturing `player.x/y` there at a state transition lags a frame — physics has already moved the player off the trigger. Set in fixedUpdate (e.g. `handleSpringCollision` snapshots `spring.x/y` into `springLaunchX/Y` the same tick `springTrailTimer` is set) or in `drawPlayer` per-frame (e.g. `fastFallAnchorX/Y` captured the moment `vy` flips upward, so a stomp bounce doesn't drag the smudge).
- **`GameLoop.particleSystem` is public** (no `private` keyword in `GameLoop.ts`). Tests can `vi.spyOn(loop.particleSystem, 'fn')` directly without `as any` casts.

## Physics & Mechanics
- Hitstop is per-player (`Player.hitstopTimer`, ~7 frames). Physics skipped but visual timers (`damageFlashTimer`, `burnTimer`) still tick. Multi-kills use `Math.max`.
- Side squash: `Player.sideSquash` triggered by wall collision (0.75) or push (0.8). Add `sideSquash: 1` to test helpers for new Player fields.
- Hazard zone collision inset 12px on each side. Lava sets `burnTimer` + `slowTimer`; thorns/ghosts only `slowTimer`.
- Ghost/hazard hits apply knockback + screen flash; thorns only slow.
- Effect zones: zero-G boosts vy\*1.03 / slows vy\*0.92, currents add vx force, geysers set vy directly. Cached as class fields — never re-filter per frame.
- Spring collision uses `bounceTimer` cooldown (0.3s). Spring spawn requires 200px vertical clearance.
- Scoring: kill = 2pts, carrot = 1pt, fall-off = respawn only. Default kill limit 16.
- `MatchState.bouncyWobble` is a Map (non-serializable).
- Game mods are runtime-only via `eff*` multipliers — never mutate base constants or arena definitions.
- `updatePlayerState()` (called inside `fixedUpdate`) always derives `player.state` from velocity: `vy != 0` → airborne; `|vx| > 10` → run; else idle. Tests that need a specific state across a fixedUpdate boundary must set the matching velocity too — e.g. `player.state = 'run'; player.vx = 200` keeps run state.
- **Horizontal wrap is center-based** (`wrapHorizontal` in `physics.ts`): triggers when `center = player.x + halfW` crosses `[0, arenaWidth)` and translates by exactly `arenaWidth` via `((c % w) + w) % w`. Player stays half-visible at the seam. The old edge-based version teleported the player FULLY off-screen on the opposite side and stranded them there if `vx` decayed to 0 (friction / released input / slowTimer) before they walked back into view.
- **`resolveOutOfBoundsPlayer` failsafe** (`physics.ts`) runs after `applyArenaConstraints` in the per-player loop. Bounds-first early-return (hot path), then delegates to `respawnPlayer` (full state reset + i-frames + safe-spawn picking) if the wrap path ever fails. `physics.ts` imports `respawnPlayer` from `stomp.ts` — function-only ESM cycle, intentional, don't inline-and-revert.
- **`renderer.ts` skips `state === 'respawning'` players** (lines ~736, ~781). They're INVISIBLE at the death position during `RESPAWN_DELAY`, not just teleport-on-respawn. When diagnosing "player disappeared / not visible" bugs, check `player.state` first — a kill landed near the wrap seam can put a player off-screen for ~`SPLAT_DURATION + RESPAWN_DELAY` before reappearing at a spawn point.
- **Determinism snapshots: TWO files**. `src/engine/__tests__/__snapshots__/regression-determinism.test.ts.snap` AND `src/engine/simulator/__tests__/__snapshots__/Simulator.determinism.test.ts.snap`. Both lock observable simulation fingerprints (positions after fixed seed + scripted inputs). Physics or wrap changes typically invalidate one or both — regenerate with `npx vitest run <path> -u` and INVESTIGATE the diff (per each test's own header comment) before accepting.

## Characters
- Pack registry must be initialized before use — `registerBuiltinCharacters()` called at module scope in `App.tsx`.
- Character sounds live in each pack via `createSound?: () => Howl` — called once at AudioManager init. Simple tones use `generateToneBuffer()`, multi-segment use `generateMultiSegmentTone()`, custom synthesis (frog) uses `floatBufferToWavDataUri()` directly. Future packs can return MP3-backed Howls.
- `defaults.ts` CHARACTERS record is mutated at lobby exit (intentional). `getAllCharacters()` derives full roster from pack registry.
- **Lobby roster**: use `getLobbyRoster()` (from `characters/preferences.ts`) for lobby/match consumers — returns the user-filtered 10-char set with random fill, cached. `getAllCharacters()` returns the FULL registry and is only for the character-selector UI itself. `assignBotCharacters` already filters via `getLobbyRoster()`. Call `regenerateLobbyRoster()` on lobby mount for fresh random fill per visit.
- **Pack name vs filename**: pack files are lowercase (`chick.ts`) but `pack.name` is capitalized (`'Chick'`). Always match by `pack.name` — never derive from filename. The `DEFAULT_SELECTED` list in `preferences.ts` and any `name === 'X'` checks must use the registered `pack.name`.
- Character emoji: use `getCharacterEmoji(name)` from `characters/registry.ts` — single source of truth. Used in React components with `.row-emoji` CSS class.
- Legs: shared `drawLegs()` in `characters/legRenderer.ts`, configured by `CharacterPack.legStyle` (shape, footStyle, dimensions). Called from both renderer.ts and CharacterSelect.tsx. Must be a pure function (output is sprite-cached).
- Rayman-style nub legs: defaults are 6px wide × 4px tall × 2px foot. When `legH <= 5`, all filled shapes (rounded/tapered/wide) render as ellipses — quad curves are invisible at this scale. Animation amplitudes are halved vs. original long-leg values. Hip attachment at `h * 0.82`.
- When scaling leg dimensions, scale animation amplitudes proportionally — large bounce/swing on tiny legs looks jittery. Also reduce squash expansion factors.
- Owl claws use explicit `footWidth`/`footHeight` overrides to stay prominent at nub scale. The claw renderer's stroke width and splay angles matter more than leg size for visual identity.
- Appendage anchors (tails, wings): use `cx - w * 0.45+`, not `cx - w * 0.3`. Body ellipse extends to `cx ± w * 0.4`, so closer anchors clip into the face. For `customEyes: true` packs, draw the appendage before the face circle/eyes so face details mask any residual overlap.

## Audio
- Audio system decomposed into `audio/` directory: `AudioManager.ts` (play/stop/mute/pause), `MusicManager.ts` (menu + arena music), `soundRegistry.ts` (declarative SFX table), `synthesis/` (pure generators grouped by category). Old `audio.ts` is a re-export shim.
- All procedural sounds are Float32Array → WAV data URI → Howler.js. No MP3 for SFX.
- Frequencies below 100Hz are inaudible on laptop speakers. Use 130Hz+ for thuds/impacts. Calibrate: generation amplitude * Howl volume should be ≥0.05 for one-shots.
- SFX cooldowns use per-player `Map<PlayerSlot, number>` (like `footstepAccumulators`) or a global number. Decay with `dt` every frame. Sound plays only when cooldown ≤ 0. Decay cooldowns BEFORE the hitstop `continue` so they don't accumulate during hitstop.
- Ambient sounds: `ArenaPack.ambientSoundConfig` with `loops` (continuous) and `periodic` (random interval one-shots). Loops tracked in `activeAmbientLoops[]`, all stopped in `stop()`. Periodic timers in `periodicAmbientTimers` Map, ticked at end of `fixedUpdate()`.
- Player-push bump sound uses global cooldown (not per-player) to prevent double-fire from both pushed players in the same frame. Detects push via `sideSquash === 0.8` (exact value set by `collidePlayersHorizontal`).
- All 11 arenas + menu have MP3 music. Each arena pack specifies `musicFile` (e.g. `'meadow.mp3'`), resolved by `audio.playMusic()` via `getArenaPack()`. Menu music uses a separate `menuMusicHowl` preloaded in `init()` — not tied to component lifecycle (persists across menu↔lobby). Suno generation prompts are in `docs/suno-arena-prompts.md`.
- `Howler.mute()` is the global kill switch for all audio. Three independent mute sources: `muted` (user toggle), `backgroundMuted` (tab hidden via visibilitychange), `gamePaused` (pause overlay). All three must be false before calling `Howler.mute(false)`. Adding a new mute source? Check all unmute paths gate on it.
- **`Howler.mute()` is NOT enough on mobile.** Phone-call interruption, screen-off, and app backgrounding move the Web Audio context to `'suspended'` (Android) or `'interrupted'` (iOS); `mute()` only flips a gain node and won't bring it back. `AudioManager.resumeContext()` calls `Howler.ctx.resume()` and is fired from the `visibilitychange→visible` handler, `setPaused(false)`, `playMusic()`, and `playMenuMusic()`. Symptom of forgetting it: **MP3 music plays (HTMLAudio path) but procedural SFX are silent (Web Audio path)** — the smoking-gun fingerprint when only one of the two stops working after an OS interruption.
- `gamePaused` is reset inside `audio.stopAllGameSounds()` — `GameLoop.stop()` runs that, so all game-exit paths (quit-from-pause, match-end cleanup, stall timeout) clear the mute automatically. New exit paths don't need explicit `setPaused(false)`, but must go through `stopAllGameSounds()` or call it directly.
- All MP3 music Howls (menu + arena) use `html5: true` — streams playback as bytes arrive instead of stalling on `decodeAudioData` behind the ~40 WAV SFX buffers that `registerAllSounds()` decodes at menu mount. New arena music Howls must set `html5: true` too. Procedural WAV SFX stay on Web Audio (no `html5` flag).
- Music preference persisted in `carrotroyale_music_disabled`, music volume scalar in `carrotroyale_music_volume` (both via `safeStorage` from `src/storage.ts`). Loaded at field init, not in `init()`.
- `Howler.playing()` is unreliable after a blocked autoplay (mobile) — set optimistically even when the browser silently rejects `play()`. For anything that runs outside a user gesture (menu music on MainMenu mount), track actual playback via Howl `on('play')/on('stop')/on('playerror')`. Arena music is safe (always post-gesture).
- **Howler `html5: true` Audio-pool double-play**: calling `play()` while a Howl is still loading spawns a SECOND concurrent instance when load completes (each `play()` claims a pool slot). The "play has actually started" event flag isn't enough — guard duplicate calls with a `*PlayPending` flag set immediately on `play()`, cleared on `'play'`/`'stop'`/`'playerror'`. See `MusicManager.menuMusicPlayPending`. Triggers in dev: React StrictMode double-mount, Ctrl+F5 races.
- **Music state subscription**: `audio.subscribeMusic(listener)` notifies on `setMusicDisabled` / `setMusicVolume` (no-op short-circuited; only fires on real change). Use with `useSyncExternalStore` for React UI mirroring music state.
- Pause only calls `Howler.mute(true)` — the arena Howl keeps running silently. Guard same-theme resume with `if (!musicHowl.playing()) musicHowl.play()`, otherwise a second concurrent instance starts at offset 0 (Howler allows concurrent playback by default).
- Audio tests: the `MockHowl` constructor in `src/engine/audio.test.ts` must stub `.on()` and `.once()` alongside `play/stop/volume/unload/playing`. MusicManager attaches event listeners in `createMenuHowl()`, so missing stubs throw at test-time.

## Arenas
- **Iso-skew visual gotcha — wall on platform**: when an iso-skewed platform sits on top of another iso platform (e.g. the lobby's brick wall on the ground), drawing the wall's body/right-face at its logical `platform.y + platform.height` makes it appear to FLOAT above the ground's cap. The ground's iso cap extends `CAP_DEPTH/2` px below its logical y (the front edge), so the wall's visuals must extend that much further down to meet it. Pass `bottomY = platform.y + platform.height + CAP_DEPTH/2` to `drawPlatformRightFace`, and grow the body fillRect by `CAP_DEPTH/2`. Collision footprint stays unchanged.
- **Iso-skew visual gotcha — ground at canvas edge**: when a ground platform reaches `x=0` (or canvas right edge), the cap's iso closing diagonal (front-left → back-left, slope of `sp = CAP_DEPTH * SKEW_RATIO` px) becomes visible as an awkward edge — the ground appears to "end" with a skewed cliff instead of continuing offscreen. Fix: shift the visual platform left by `sp` (use a `visPlatform: Platform = { ...platform, x: platform.x - sp, width: platform.width + sp }` and pass that to `drawPlatformCap` and the body fillRect), so the diagonal sits in negative-x space. Collision still uses the original `platform.x`. Symmetric fix for ground at the right canvas edge.
- Arena pack registry must be initialized before use — `registerBuiltinArenas()` called at module scope in `App.tsx`. Nav data is embedded in each pack's `navData` field and auto-registered.
- `ArenaPack` in `arenas/types.ts` merges layout (platforms, spawns) + visuals (sky, draw functions) + translations + musicFile into one interface. `toArena()` / `toThemeConfig()` extract the old types for consumers that need them.
- `platforms[0]` is always ground (or first ground segment, detected by `p.y >= 650`).
- `allowFallOff` arenas: set `hills[].baseY` to 780+ to push hills offscreen.
- Tall narrow platform collision: `landingFromAbove` guard prevents side-approach snapping. Prefer wider-than-tall blocks.
- Solid building blocks need `noSpawnZones` covering interiors.
- `arenaId: 'random'` resolved in `Match.tsx` via `resolveArenaId()`, not in store.
- `themes/` directory still exists for shared infrastructure: `types.ts` (ThemeConfig interface used by Renderer), `drawPrimitives.ts` (shared draw functions), `utils.ts` (utility functions). Individual theme files are gone — visuals live in arena pack files.

## Reactive Decorations
- **System** (`gameLoop/cosmetics/ReactiveDecorationSystem.ts`): arena-anchored decorations with wind sway, velocity-driven bend, stomp shake, burst triggers. Constructed by GameLoop; populated via `ArenaPack.buildReactiveDecorations(arena)`.
- **Bend dynamics are spring-damper** (NOT proximity-duration). Force per (player × in-radius) = `playerVx × proxFactor × inst.bendCoeff`. Stiffness 28, damping 5 (ζ≈0.47, under-damped). `proximity.magnitude` = equilibrium bend at `WALKING_SPEED_REF` (200 px/s) — kind authors think in pixels.
- **Layer** is `'prePlayer'` or `'postPlayer'` (drawn before / after player loop). NOT `background`/`foreground` — those names are misleading because both render mid-pipeline.
- **Use `createReactiveInstance({...})`** factory in arena packs — fills runtime defaults (excitement, shakeDecay, bendValue, bendVelocity, bendCoeff). Don't hand-write the zeros.
- **Use `composeBend(inst, swayPhase)`** in draw fns — combines wind muting `(1 - excitement)` with `inst.bendValue`. Don't add them manually.
- **Per-kind mutable runtime state lives in `inst.data`** with a `resetData` callback at registration. Module-level WeakMaps are an anti-pattern — they survive arena switches and don't reset on guest reconnect.
- **`proximity.mode`**: `'lean'` (bend with player motion, default), `'flee'` (away), `'excite'` (no bend — just excitement scalar; used by dandelion to trigger seed-burst).
- **60Hz opt-in** via `highFrequency: true` for fast-moving creatures (butterflies, bees). Default 30Hz bucket runs at 15Hz with 2× dt via cosmetic-stagger.
- **`isLivePlayer(p)`** in `themes/utils.ts` — use it instead of inlining `!p.active || p.state === 'splat' || p.state === 'respawning'`. Multiple cosmetic systems duplicate this guard inline; new code should not.
- **Static decorations stay in `drawForegroundNature`/`drawBackgroundNature`** so they bake into the OffscreenCanvas cache. Only opt into the reactive system if the kind genuinely needs per-frame reactivity (proximity, stomp, burst). Wind-only sway alone is not worth the per-frame cost.

## AI
- Awareness uses single pass over `state.players` — no `.filter()` loops.
- Evaluators must not allocate arrays — runs 60x/bot/sec.
- Jump suppression: 3 layers (tight-space check, threshold 0.55, cooldown 20 frames).
- Stuck recovery: nav-directed jump after 45 frames of <2px movement.
- Chase/priority evaluators defer to nav when enemy on different level (|dy| > 40).
- Fat bots flee like hurt bots (skip chase/stomp/platformSeeking).
- Nav data in pack files (between `NAV-DATA-START`/`NAV-DATA-END` markers) is generated — never hand-edit. Re-run `npx vite-node scripts/generateNavData.ts` after arena/physics changes.
- Nav graph doesn't model intra-platform obstacles or blocking ceilings. Small obstacles handled by stuck recovery; impassable barriers require splitting ground in arena definition.
- Nav ceiling gap must exceed 174px (MAX_JUMP_HEIGHT) or phantom edges are created.
- Lobby bots (`botLobbyInput()` in `lobbyGame.ts`) return `InputState` and go through `applyInput` like humans. Behavior (walk-to-zone + wall-jump) remains lobby-specific and does not share code with match AI.
- Lobby runs no `cosmeticStep` — any renderer-consumed cosmetic timer (`idleAction*`, `animFrame`, `squashScale`) must be ticked manually inside `LobbyGame.step()`. Mirror the logic from `gameLoop/cosmetics/playerCosmetics.ts`.

## Performance
- Sprite cache: keyed by `name_state_animFrame_fastFalling_sqKey`, 600-entry cap. `sqKey` = `Math.round(squashScale * 10)`. Breathing (2% scale) excluded from key. Idle-action geometry must use `IdleAction.applyAfter` (overlay outside the cache), not in-sprite branches on `isIdleAnim`/`idleT` — those freeze at first cache hit because they're not in the key.
- Gradient cache: lava, zero-G, ghost, bouncy gradients cached in Maps by position.
- HUD cache: 1280x90 OffscreenCanvas, redraws on score/timer/player changes.
- **Foreground-nature cache**: `Renderer._fgNatureCache` is a 1280×720 OffscreenCanvas that captures `theme.drawForegroundNature(ctx, arena)` output. Built in `renderBackground()` (arena-load + render-scale change), blit at identity transform in `renderFrame`. Mirror is baked in. Test envs without OffscreenCanvas fall back to direct draw. Was the biggest single perf win in the 2026-04-25 pass — meadow 25.6ms→7.5ms, eliminated GC pauses up to 166ms. Any future foreground-nature additions go through this cache automatically as long as they use only static inputs (no `time`, RNG, runtime state).
- Particle pool: free-list via `emitParticle()`, capped at 600.
- Platform filter cache: `getFloatingPlatforms()` uses WeakMap.
- AI throttle: decisions every 3rd frame, staggered by `botIndex % 3`.
- **globalAlpha rule (refined)**:
  - **Static alpha**: bake into `rgba()` fillStyle, don't mutate `ctx.globalAlpha` per call. Saves a state mutation.
  - **Dynamic per-element alpha** (e.g. star twinkle, firefly pulse): set `fillStyle` once with opaque color (`'#FFFFFF'`), modulate `ctx.globalAlpha` per element. Avoids the rgba template-literal string allocation per element. Wrap the function in `save/restore` so the mutation doesn't leak. See `drawDayNightCycle`.
- Off-screen culling for particles and gibs.
- `fastMath.ts`: lookup tables for `fastSin`/`fastCos` — visual effects only, keep `Math.sin`/`Math.cos` for physics. **Note: V8 inlines `Math.sin` to FPU instructions; the lookup table isn't always faster on desktop.** Don't blanket-convert without measuring at the call site. Style consistency within a file is reasonable.
- **`fastSin`/`fastCos` resolution gotcha**: 360-entry lookup table with `|0` integer truncation — no interpolation. Output only changes when the input crosses a 1° (≈0.0175 rad) boundary. Any `fastSin(time * k)` where `k < ~1.05 rad/s` looks choppy at 60Hz render (the value steps less than once per frame; multiplied by a large amplitude this becomes visibly discrete). Symptom: the affected element appears to update at ~5–10fps. Real example: underwater fish-school sweep used `fastSin(time * 0.18)` for cxBase across the canvas — the 1° step size at 0.18 rad/s gave ~10Hz updates and was perceived as "5fps choppy". Fix: use `Math.sin`/`Math.cos` for slow oscillations (sub-rad/s). Per-frame velocity is fine on `fastSin`/`fastCos`.
- **Weather particle shape branch**: arena packs' `drawWeatherParticle` should branch by shape. Symmetric shapes (circles, ellipses with ratio 1:1) skip `save/translate/rotate/restore` — draw directly at `(w.x, w.y)`. Asymmetric (rectangles, ellipses with ratio ≠ 1, offset features) keep the transform. Same applies to `drawWeather` defaults in `rendering/particles.ts` for `'snow'`/`'ember'` types.
- **Combine N draws into 1 path**: per-element `beginPath/draw/fill` (or stroke) in a tight loop is wasteful when colors match. Build one path with sub-paths (use `moveTo` before each `arc` to start a new sub-path so circles don't connect with lines), call `fill()`/`stroke()` once at end. Pattern landed in `drawZeroGZone` (12 fills→2), `drawBouncyPlatformOverlay` arrows (N→1), `drawDayNightCycle` sun rays (4→1).
- **Hoist `setLineDash` arrays**: array literals passed to `setLineDash` allocate. Module-scope `const ZEROG_DASH = [8, 5]; const NO_DASH = [];` reused across calls.
- **Precompute static loop values**: scattered positions like `(i * 137 + 83) % WIDTH` recomputed every frame should be hoisted to module-scope `Float32Array` initialized once. Pattern landed in `drawDayNightCycle` for stars + fireflies.
- **Perf measurement**: `npm run perf -- --arena=X` runs the e2e perf profile with vsync uncapped, random P1 input, sourcemapped bundle. Reports go to `test-results/perf/report.md`. **Save reports to `perf-runs/<arena>/` between runs** — Playwright wipes `test-results/` on each invocation. Run-to-run variance ~5%; trust deltas of >0.3ms/frame, treat smaller as noise. Use volcano or meadow for shared-rendering hot-path measurements (more signal than rooftops).
- **perfTrace**: orchestrator-level spans (`fixedUpdate`, `cosmeticStep`, `tickCosmetic`, `renderFrame`) use `measure()` for try/finally + early-return safety. Per-system leaf spans (`gameplay.*`, `cosmetic.*`, `simulator.*`) use `begin/end` to avoid per-call closure allocation (~4% observer effect at 60Hz). Systems do NOT self-instrument — orchestrators wrap them externally so dot-namespaces stay consistent. perfTrace spans typically capture ~25% of frame budget; the rest is GPU composite/paint/presentation. Don't ship perf claims based on perfTrace deltas alone — confirm with `npm run perf` wall-clock percentiles.
- **CanvasGradient on large fills is catastrophic** (~5ms/frame full-canvas at 1280×720). The browser evaluates the gradient function per-pixel — caching the gradient *object* doesn't help. Use `bakeVerticalGradientStrip(height, build)` from `themes/utils.ts` to pre-bake into a 1×N OffscreenCanvas, then `drawImage(strip, …)` stretched with `imageSmoothingEnabled = false`. For shaped fills, combine with `clip()`. Sites converted in the round-12 pass: `winterLake.drawSceneTint`, `effects.getAfterglowGradient`, `hazards.drawCurrentZone` water body, `hazards.drawZeroGZone` background, `hazards.drawHazardZone` lava body + halo. Full pattern + concrete numbers in `docs/perf-patterns.md`; recurring-pattern catalog in `.claude/skills/performance.md`.
- **Counter-example: don't cache cheap path fills to a large canvas.** Tried caching the waterfall drift band (3 sin-wave layers, ~660px tall, full width, refreshed at 10Hz) — regressed perf 0.5–1.9ms across all 3 affected arenas. Per-frame `drawImage` of a 1280×660 translucent canvas costs more on the compositor than rasterizing 3 path fills. The gradient-strip pattern works only because the source is 1×N (tiny); destination size is irrelevant for sampling cost when smoothing is off. Rule: cache when replacing per-pixel function evaluation; don't cache when replacing a handful of cheap fills.
- **Particle alpha bucketing**: when N particles each have unique alpha (driven by life/distance/etc.), N `fill()` calls are wasteful. Quantize alpha into 4–6 buckets, group particles by bucket, batch each bucket as one path with `moveTo` + `arc` sub-paths and a single `fill()`. Round-12 application: waterfall spray 48 particles → 5 fills, mist 10 → 3 fills. Net 58 state changes/frame → 8.

## Mobile / Touch Input
- `TouchInputManager` follows same `attach()`/`detach()`/`getInput() → InputState` contract as `InputManager`. Integrated via `getPlayerInput()` touch branch in gameLoop.
- `isTouchPrimary()` result is cached at module scope — safe to call frequently, but `?mobile` URL param override only works on first call.
- Touch coordinate mapping: cache `getBoundingClientRect()` on attach + resize. NEVER call per-touch-event (causes layout reflow at 60-120Hz).
- `e.preventDefault()` on touch events blocks synthetic click events on buttons. Always check `target.tagName === 'BUTTON'` before preventing default.
- `haptics.isLocal(player.id)` gates all vibration calls — only vibrate for events involving the local touch player. Haptic calls are inside event-conditional blocks (stomp, hazard hit, spring, landing) — they do NOT run every frame per player.
- `touchSlot` defaults to the first human player (P1). For online guests, call `setLocalSlot(slot)` after GameLoop creation — otherwise touch input targets P1 (the host) instead of the guest's actual slot.
- **`getInputAny()` must use `getInputForPlayer(airborne)`, not raw `getInput()`.** Guests send `getInputAny()` to the host for network input. If it reads raw input, the airborne-tap→fast-fall conversion is lost — physics receives `{jump: true}` on an airborne player (ignored) instead of `{down: true}` (fast-fall). The touch player's airborne state is looked up via `touchSlot` from `state.players`.

## Simulator (pure simulation core, Node-safe)
- `src/engine/simulator/Simulator.ts` owns: state, settings, arena (+originalArena, theme), eff* physics, RNG (rng + aiRng), aiControllers, playerInputs, all 7 gameplay systems, `_phase`, `_resimulating`, `_loadingGeneration`. NO browser/audio/renderer/Howler/haptics/touchInput/KeyboardManager imports — verified by `regression-no-browser-apis.test.ts`. Adding a new browser-bound dependency to Simulator will fail that scan; route through `SimulatorEvents` or one of the typed emitter interfaces (`ParticleEmitter`, `TouchInputProvider`, `HapticEmitter`).
- `SimulatorEvents` (in `simulator/types.ts`): 10 callbacks — `onSfxRequest`, `onMusicStartRequest`, `onMusicStopRequest`, `onSoundStopRequest`, `onSoundVolumeRequest`, `onAllGameSoundsStopRequest`, `onPhaseChange`, `onMatchEnd`, `onPlayerLanding` (haptics), `onStompHaptic` (haptics). Internally normalized to `Required<SimulatorEvents>` with no-op defaults so call sites don't need optional-chaining at 60Hz. Audio side effects (play/stop/volume) and haptics are routed through callbacks rather than direct imports so gameplay code stays Node-pure.
- `Simulator.fixedUpdate(dt)` is the gameplay tick (lifted verbatim from old GameLoop.fixedUpdate body). Order: countdown → hazard → carrot → arenaEntity → per-player physics → effectZone → bouncy → pigeon → carrot pickup → effectZone tick → stomp → match. Order matters; the regression snapshot will catch reordering.
- `Simulator.setPhase(phase)` fires `onPhaseChange` + `onMusicStartRequest` + `matchSystem.init()` on the loading→playing edge. `Simulator.switchArena` rebuilds gameplay systems via private `_buildSystems()` and fires `onAllGameSoundsStopRequest` + `onPhaseChange('loading')`.
- `Simulator.setSfxCooldownsGetter(() => map)` is called once at GameLoop construction (line ~138). The getter uses lazy `() => this.playerTransitionSystem.getSfxCooldowns()` — when GameLoop's playerTransitionSystem is replaced (switchArena), the same getter still returns the new cooldowns map. Calling `setSfxCooldownsGetter` again post-switchArena would be a redundant rebuild.
- `_boundParticleEmitter` indirection: GameLoop builds the ParticleSystem AFTER constructing Simulator (ParticleSystem needs the geyserIndexMap from Simulator's ArenaEntitySystem). The Simulator stores a `_particleEmitter` field that GameLoop swaps post-construction via `simulator.setParticleEmitter(particleSystem)` — the gameplay systems already hold a stable reference to the swap-aware indirection object, so the swap takes effect without rebuilding any system.
- `GameLoop` is now a browser adapter: owns Renderer, RAF loop, KeyboardManager, TouchInputManager, ParticleSystem + 4 cosmetic systems, `_audioEnabled`/`_networkMode`/`_cosmeticLead`/`onPhaseChange`. It constructs Simulator, subscribes to events (`onSfxRequest → audio.play(name) gated by _audioEnabled`, etc.), and its `fixedUpdate(dt)` delegates to `simulator.fixedUpdate(dt)` then runs cosmetic systems separately. Public GameLoop API (Match.tsx, NetMatch consumers) is preserved; methods delegate to `simulator.*`.

## Headless / ML pipeline
- `src/engine/headless/` is Node-only and intentionally outside the browser-pure path (it imports `node:fs` for NDJSON file recording — gated by a triple-slash `/// <reference types="node" />` directive in `recording.ts`, so only that file pulls @types/node).
- `HeadlessRunner` composes Simulator + per-slot PlayerInputs. Optional `RecordingConfig` wraps recorded slots' PlayerInputs in `ActionCapturingInput` (additive — Simulator sees the same action), snapshots pre-tick observations, computes per-slot rewards via supplied `RewardShaper`s, emits one `Sample` per (slot, tick) to a `MatchRecorder`. Last tick of the episode has `done: true`.
- Bots that need RuleBasedBot wrapping the simulator's AIController must be registered post-construction via `runner.getSimulator().setPlayerInput(slot, new RuleBasedBot(...))` — the AIController is created inside Simulator's constructor.
- `extractObservation(state, slot, arena, settings, out)` writes 98-float egocentric observation: 10 match-context (mods + scoring + limits + time progress) + 12 self + 12×4 opponents + 3×4 carrots + 4×4 hazard zones. Caller-provided buffer to avoid per-tick alloc. Self and opponent blocks both carry the four hazard/buff timer norms (`fat`, `slow`, `invincible`, `burn`) — symmetry matters because `invincibleTimer > 0` blocks stomps in `stomp.ts`, so a policy that can't see opponent i-frames will waste tempo. Match context lets one trained policy adapt across regimes (normal vs carrotChase, kill-limit 8 vs 32, etc.) without retraining — `killScoreValue_norm` is 1 normally, 0 in carrotChase. Egocentric X uses `wrapDx` (mirrors `ai/awareness.ts`) — arena wraps horizontally via `physics.wrapHorizontal`, so a 20px-around-the-seam opponent encodes as `dx≈-0.016`, NOT `+0.984`. Y axis doesn't wrap.
- `RewardShaper` is per-slot stateful with **event-based detection** (NOT score-delta heuristics — those silently miss kills in `mods.carrotChase` where stomps award 0 score). Kills/deaths come from `state.killFeed` (timestamp-baseline scan, trim-safe). Carrots come from `state.stats.perPlayer.get(slot).carrotsEaten`. Hazard hits come from rising edge of `slowTimer` or `burnTimer`. Fall-off comes from `state→'respawning'` without a prior `'splat'`. Match end fires on `matchOver` false→true transition. Defaults match the game's 2:1 kill:carrot ratio: kill +1.0, carrot +0.5, death -1.0, win +5.0, loss -2.0, hazardHit -0.3, burnTick -0.005, fallOff -0.5, plus per-tick survival +0.001 / airborne -0.0005. Defaults exported as frozen `DEFAULT_REWARD_WEIGHTS`. All weights tunable via the `RewardWeights` constructor arg, `--reward.<key>` CLI flags, or `--rewards-file <json>` in `scripts/selfPlay.ts` (resolved weights are stamped into every NDJSON header's `tags` for reproducibility). Full wire-format spec: `docs/headless-recording-format.md`.
- `BatchedPolicy` interface enables one neural-net forward pass per tick across all slots (the bottleneck for ML throughput). `PolicyBroker.tick(state, arena, settings)` extracts observations into a flat batch and calls `policy.step(slots, obsBuffer, actionBuffer)`. Per-slot `PolicyInput` adapters read their pre-computed action — `getAction` does NOT trigger inference.
- `NDJSONFileRecorder` streams `{type:'header',...}\n{type:'sample',...}\n{type:'end',...}\n` lines. End record contains a summary subset (winner, ticks, reason) — `finalState` has Maps that don't survive JSON, so it's dropped.
- Example pipeline: `npx vite-node scripts/selfPlay.ts -- --episodes 5 --arena meadow --out run.ndjson --seed 42`. Produces N episodes appended to a single NDJSON file. Use `--reward.<key> <value>` or `--rewards-file <path>` to override defaults per run; the resolved weights are recorded in every header's tags. NDJSON wire format is fully specified in `docs/headless-recording-format.md` — keep that doc in sync with `OBSERVATION_SIZE` / `DEFAULT_REWARD_WEIGHTS` changes.

## Lighting

- **Per-frame, screen-space, post-sprite-cache.** Hard rule from `feat/rim-light` and `feat/character-outlines` post-mortems. Never bake lighting into a sprite cache, the foreground-nature cache, or any other cached canvas. The `AmbientPipeline.composite()` call sits inside the hitstop/screen-shake transform but AFTER all entities are drawn — lights ride the shake, never get baked.
- **Composite point:** in `renderer.ts:renderFrame`, the order is `beginFrame()` at top, then all bg/fg/effects rendering as before, then `composite()` immediately before `ctx.restore()`, then brightness pass, then `ctx.restore()`, then HUD on dedicated canvas. HUD is NEVER tinted (ref §19.7 — bloom on UI = eye cancer).
- **Cross-fade BG + multiply fg-tint (CSS-composited)**: Two stacked DOM elements drive nighttime darkening, no per-frame canvas work. `bgNightCanvas` (sibling of `bgCanvas`, z between bg and fg) gets the day BG drawn into it + a uniform tint baked once per arena-load; renderer drives its `style.opacity` from `lighting.getBgNightOpacity()` for atmospheric BG darkening. `fgNightTint` div (above fg, below hud) has `mix-blend-mode: multiply`; renderer drives its `style.opacity` from `lighting.getFgTintOpacity(bgOpacity)` for color-preserving sprite darkening. The multiply layer triggers Chromium GPU layer promotion → fg gets its own compositor layer (perf win on top of the visual win). When wired, `AmbientPipeline.composite()` is a no-op. **Lobby and tests** (`CharacterSelect.tsx` + `renderer.test.ts`) don't wire either DOM element and stay on the source-over fillRect fallback — at lobby's noon-pinned dayPhase the tint is below threshold so the fallback is also a no-op. **L4 evolution**: arenas opt in to per-arena hue-shifted nights via `ArenaPack.bgKeyframes` later — same infrastructure, just multiple BG keyframes; the multiply fg-tint stays universal. See `perf-runs/lmode-comparison/REPORT.md` for the 7-mode A/B test that picked this approach, and `docs/superpowers/reviews/2026-05-07-lighting-l1-cross-fade-review.md` for the post-implementation review.
- **Mid-match bg writes update bgNight**: `bakeGibs` and `renderBloodDrips` write to bgCanvas (kill marks). They set `_bgNightDirty`; the next `renderFrame` re-bakes bgNightCanvas once, regardless of how many bg-mutating paths fired in the frame. `_bakeBgNightVariant` clears the dirty flag only when it actually bakes (gated on `lighting.isEnabled() && bgNightCanvas`), so a kill landed while lighting=off re-bakes on the first frame after re-enable. Without this, kills are invisible at midnight on dark arenas (haunted_graveyard, volcano).
- **dayPhase convention** (matches existing `drawDayNightCycle`): `0 = noon, 0.25 = sunset, 0.5 = midnight, 0.75 = sunrise`. `nightIntensity = (1 - cos(dayPhase * 2π)) / 2`. `themeToAmbient` consumes this convention. Network guests must wrap-aware-lerp dayPhase in `interpolation.ts` — a naive lerp passes through 0.5 at the seam (full midnight flash every cycle).
- **Determinism rule.** Any phased lighting effect (flicker, twinkle, pulse) MUST derive its phase from `SeededRNG.fromTick(seed, state.tick)` (see `engine/seededRng.ts`). Never `Math.random()`, never `performance.now()`. Pass a per-emitter seed (e.g. hash of entity position or id) so co-located effects don't end up perfectly correlated. Reason: host-authoritative netcode allows cosmetic divergence in principle, but consistent appearance across host/guest is a quality bar for player-visible lighting.
- **Kill switch:** `?lighting=off` URL param + localStorage key `carrotroyale_lighting` ('on'/'off'). When set, `AmbientPipeline.isEnabled()` returns false; renderer skips composite, brightness pass, AND the bgNight bake. E2E regression `lighting-off-regression.spec.ts` enforces it. (Older builds used `carrotroyale_lighting_off` with '1' = off; that key is silently abandoned on first load — kill switch defaults to on.)
- **Accessibility scaffolds (URL + localStorage, no UI in M1):**
  - Brightness: `?brightness=0.5..1.5`, `carrotroyale_brightness`. Final composite multiplier; skipped at 1.0.
  - Photosensitivity: `?photosensitivity=on|off`, `carrotroyale_photosensitivity`. Caps ambient floor at `rgb(120,130,160)` and sun intensity at 70% in M1; L2+ flicker reads the flag too.
- **Perf tiers:** `low | med | high`, default `med`. URL `?perfTier=...`, storage `carrotroyale_perf_tier`. M1 only implements `med`; low/high fall through. L2+ branches.
- **Pure light-math module:** `ambient.ts > themeToAmbient(theme, dayPhase, photosensitivity, scratch?)` is the single ambient producer for L1. L2 will add `Light` primitives + `EmitterPipeline`; until then the pipeline owns ambient only.
- **L2 emitter compositing:** `Lighting` orchestrator holds `ambient: AmbientPipeline` (renamed from L1's `LightingPipeline`) + `emitters: EmitterPipeline`. `Light` plain-data type (point/spot, RGB, falloff, optional flickerSeed). `lightStamp(ctx, light, tick)` is a pure function with `'lighter'` blend. Single `lightCanvas` DOM sibling at z=5 with `mix-blend-mode: screen` so additive contributions punch through the fg-night-tint multiply at composite time. Static catalog (`ArenaPack.lights`) baked once into an `OffscreenCanvas` cache at arena-load; per frame: `clearRect` → `drawImage(cache)` → dynamic stamps + flicker overlays. Light layer opacity tracks `bgNightOpacity` so emitters fade in with night. (Bakeoff vs a split static/dynamic two-canvas layout was a wash — see `perf-runs/l2-emitter-comparison/REPORT.md`. Combined wins on simplicity + GPU memory.)
- **Per-arena lights catalog:** add `lights: ReadonlyArray<Light>` to an `ArenaPack` to declare static emitters (e.g. castle's 5 torches). Loaded automatically by `Renderer.renderBackground` via `getArenaLights(arena.id)`. Dynamic emitters synthesized in `_synthesizeDynamicLights` from entity state — no `Player`/snapshot schema changes:
  - **Per-player aura** — soft warm glow on every live player; intensity + radius ramp during respawn invincibility (the "spawn pillar" effect — `Player.invincibleTimer / INVINCIBLE_DURATION` drives the boost).
  - **Carrot glow** — subtle warm-orange light per active carrot so they stay visible at night. Fresh carrots get a brief brightness pulse over `CARROT_SPAWN_FLASH_S` keyed off `Carrot.spawnTime`.
- **Determinism (L2 flicker):** per-emitter `flickerSeed` keyed via `SeededRNG.fromTick(seed, tick)` where `tick = floor(matchState.timeElapsed * 60)`. Co-located emitters with distinct seeds desync. Guests see ~2-tick flicker lag (acceptable per L2 spec).
- **What lives where:** `effects.ts > drawDayNightCycle` retains sun, moon, stars, fireflies, sunset afterglow (procedural celestial drawing). The pipeline owns ambient darkening; the celestial drawing in `effects.ts` is independent of the pipeline.

## Network Multiplayer (Host-Authoritative)
- **Architecture**: Host runs full GameLoop (identical to local play), broadcasts binary snapshots to guests every tick. Guests interpolate between snapshots and send inputs to host. No determinism requirements — host is the single source of truth.
- **ICE servers**: `ICE_SERVERS` in transport.ts configures STUN + TURN. TURN required for mobile-to-mobile (symmetric NAT). Currently uses free metered.ca Open Relay.
- **Trystero MQTT signaling**: Replaced PeerJS. Serverless, zero infrastructure. Vite config needs `optimizeDeps.include: ['trystero']`.
- `fixedUpdate` is public in network mode. Accepts optional `networkInputs` map — host provides guest inputs via `HostAuthority.getNetworkInputs()`.
- `renderFrame(frameDt)` must receive frame delta in network mode to decay `slowMotion`/`screenFlash`/`hitstopZoom` (normally decayed in `loop()`).
- **`getInputAny()` must merge touch + keyboard input.** Guests send `getInputAny()` to host. If touch input isn't merged, mobile guests send empty inputs.
- **Timer decrements MUST use `Math.max(0, ...)`** to prevent negative values. `Math.fround()` can produce small negatives (e.g. -0.017). Negative timers encoded as Uint8 wrap to 255 in snapshots, causing permanent visual artifacts on guests. `encodeTimer()` has defense-in-depth `if (timer <= 0) return 0`.
- **Host input fairness delay**: Host buffers own inputs in a ring buffer, reads `delayFrames` behind. Delay adapts to guest RTT.
- **Guest loop**: No fixedUpdate — applies snapshots then calls `cosmeticStep(dt)` (same method as host). Visual timer decay for smooth interpolation stays in the guest loop.
- **`cosmeticStep(dt)`**: Shared cosmetic code path for both host and guest. Handles all sounds, particles, VFX, environment (wildlife/fog/pollen), and state-transition detection (stomp, jump, land, spring, etc.) via prev-state comparison. Host calls it after `fixedUpdate()`. Guest calls it after `applySnapshotToState()`. Minor host-only effects (crouch, zero_g, splash, pigeon_scatter, crowd, periodic ambient) remain in fixedUpdate.
- **Half-rate cosmetic (`tickCosmetic(dt)`)**: Production loops (local, host, guest) call `tickCosmetic(dt)`, which accumulates dt and only forwards to `cosmeticStep` once per `COSMETIC_INTERVAL` (2× FIXED_TIMESTEP, ~30Hz). Render stays at 60Hz; particle motion, SFX cooldown decay, and transition detection run at half rate. Per-step dt is capped at `COSMETIC_MAX_STEP` (4× FIXED_TIMESTEP) so tab-switch recovery doesn't dump seconds of work into one step. Tests call `cosmeticStep(FIXED_TIMESTEP)` directly to exercise the unthrottled per-tick behavior. When adding new cosmetic logic, remember it sees ~33ms dt and runs every other frame — transitions that flip on/off within a single 33ms window may be missed.
- **Render-time particle extrapolation**: `Renderer.renderFrame(state, arena, particles, cosmeticLead)` accepts seconds since the last cosmeticStep (`GameLoop.getCosmeticLead()`). The lead is forwarded to `drawParticles`, `drawGibs`, `drawConfetti`, `drawWeather`, and `drawFireworks`, which extrapolate position via `x + vx * lead`, `y + vy * lead` (and rotation via `rotation + rotationSpeed * lead` where present). This smooths half-rate motion to near-60Hz visual quality. New particle-style draw functions taking `(x,y,vx,vy)` entities should accept `lead = 0` and apply the same extrapolation. Sparkle/jitter terms keyed off position must use the *raw* `p.x`/`p.y` (not extrapolated) to stay stable across frames — see `drawFireworks` sparkle phase for the pattern.
- **Renderer signature changes**: `renderer.test.ts` has 40+ direct `renderer.renderFrame(state, arena, [])` call sites. New params on `renderFrame` should default-value (e.g. `cosmeticLead = 0`) rather than be required, otherwise every test needs updating.
- **Snapshot encoding**: Player timers as Uint8 frame counts (`Math.round(timer * 60)`, 0-255). Positions as Float32.
- **Interpolation**: `EntityInterpolation` uses frame-based interpolation with adaptive delay (2-5 frames based on snapshot gap detection). Extrapolates up to 4 frames using velocity + gravity when snapshots are late. Only x/y/vx/vy are lerped; timers/state use "after" snapshot. Sequence validation discards out-of-order packets.
- **Client prediction was tried and abandoned** — constant rubber-banding due to physics divergence in complex arenas (springs, geysers, player pushing, zero-G, etc.). `ClientPrediction` class still exists for reconciliation but `predict()` is dead code.
- **Input Echo system** (`net/inputEcho.ts`): instant visual feedback for the guest's local player WITHOUT position prediction. Overrides facing, squashScale, sideSquash, fastFalling, expression based on raw input (animFrame echo removed — caused walk shake). Position always from host snapshots. Hysteresis locks (RTT + 50ms) prevent snapshot-vs-echo flicker. Suppressed during death/respawn. Kill switch: `?noecho` URL param.
- **Input redundancy**: Guest sends last 8 inputs per packet (ring buffer). Host iterates all bundled inputs with per-slot `lastConsumedFrame` tracking to recover from burst packet loss. Protocol already supported 16 bundled inputs.
- **Delta compression (DISABLED)**: Infrastructure exists (ACKs, `createDelta`/`applyDelta` in core/) but disabled due to baseline mismatch from unreliable ACK delivery. Host always sends full snapshots. See "Delta compression disabled" bullet below for details.
- **Reconnection window** (20s grace): On guest disconnect, `startReconnection()` retries `transport.joinRoom()` every 1.5s (4 attempts → 6s total). Host enters grace period (`disconnectedSlots` Map) instead of immediate removal. `RECONNECT_REQUEST` (0x15) / `RECONNECT_SYNC` (0x16) protocol messages. Match.tsx shows "Reconnecting..." overlay.
- **Stall detection** (guest-side): Tracks `lastSnapshotTime`. 500ms → `onStall(true)` ("Connection Unstable" banner) + sends `CONNECTION_UNSTABLE` (0x18) reliable hint to host. Snapshot gap no longer auto-triggers reconnection — that role moved entirely to transport's `onPeerDisconnected` (pong timeout). Previously the 3s gap trigger fired while WebRTC was still alive, causing reconnect attempts to be rejected by the host (hasActivePeer=true) for ~7 seconds. **Must check `!state.matchOver`** — host stops sending snapshots after match end.
- **`transport.joinRoom()` cleans up prior Room**: calls `this.room.leave()` (fire-and-forget), clears `this.peers`, nulls send actions, resets RTT/jitter. Prevents channel leaks and stale peer entries during reconnect cycles.
- **Loading phase handshake**: Host waits for `MsgType.LOADED` (0x17) from every expected guest AND its own `markHostLoaded()` before flipping `state.phase = 'playing'`. Hard timeout: `NetMatch.LOADING_TIMEOUT_MS = 15000` — any guest that hasn't sent LOADED within 15s is treated as disconnected and the match proceeds. Guest learns about host phase transitions via snapshot-applied `state.phase`; `startGuestLoop` detects the change via `_prevGuestPhase` and fires `onPhaseChange`.
- **Guest network warm-up gate**: `runLoadingTasks` accepts an optional `netMatch` arg; when present, the loading screen also waits for the snapshot stream to warm up (≥12 snapshots + ≥250ms since first arrival + `transport.currentRtt > 0`, 4s graceful timeout). Host's `waitForGuestNetworkReady` short-circuits, so the call site can pass `netMatch` unconditionally. This absorbs the early-match warm-up window (cold sprite cache, JIT, adaptive interpolation delay still settling, host's input-fairness delay computing against a stale RTT) into the loading screen instead of the player seeing it as choppy gameplay. Without it, the first 10–20s of online play look stuttery on low-end Android.
- **Phase-gated cosmeticStep**: Host and guest both early-return from `cosmeticStep(dt)` when `state.phase === 'loading'` — prevents spurious transition sounds on guests as the first snapshot establishes the prev-state baseline.
- **Cosmetic JIT warmup during loading (guest)**: The phase-gated early-return means the cosmetic hot paths (5 systems × per-player × per-entity transition detection) never JIT during loading; the first frame after phase flips to `'playing'` then has to compile all of them at once and blows frame budget on cold low-end Android. `GameLoop.warmupCosmeticDuringLoading(dt)` runs the systems with `resetCosmeticBaselines()` called every frame so transition detection finds prev==curr and fires nothing — pure JIT bait. Wired into `startGuestLoop`'s tickCosmetic step (loading→`warmupCosmeticDuringLoading`, playing→`tickCosmetic`). Side effect: wildlife/fog/pollen advance during loading (hidden under the overlay), so the world is already in motion the moment the overlay lifts.
- **Connection-unstable banners**: Two distinct strings so players know which side is slow. Own stall → `connection_unstable_mine` ("Your connection is unstable"). Peer stall (received via `CONNECTION_UNSTABLE`) → `connection_unstable_them` ("{{name}} has a slow connection"). Wire via `NetMatchConfig.onGuestConnectionUnstable(slot, stalled)` which resolves the name via `useGameStore.getState().online.playerNames[slot]`.
- **Consumed-jumps contract**: `hostAuthority.consumeGuestJumps(slots?)` only clears jump flags for the given slot list. The host loop in `netMatch.startHostLoop` snapshots which slots have `jump=true` at the moment `fixedUpdate` reads the ring, and passes only those to `consumeGuestJumps`. A jump latched by an INPUT message that arrives between `fixedUpdate` and `consumeGuestJumps` is preserved for the next tick — tests can still call `consumeGuestJumps()` with no argument to clear everything.
- **Loading timeout callback**: `NetMatchConfig.onLoadingTimeout(slots)` fires on the host when `LOADING_TIMEOUT_MS` (15s) elapses and one or more guests never sent LOADED. Match.tsx uses it to flash a "Starting without X" banner. The same code path disconnects the laggard slots in-state and then flips phase to `'playing'`.
- **Interpolation reset on reconnect**: `SnapshotInterpolation.reset()` and `EntityInterpolation.reset()` flush the ring buffer, reset `lastReceivedFrame` to -1, and drop adaptive delay tracking. `NetMatch.completeReconnection()` calls `interpolation.reset()` plus clears `_guestMatchOverFired` and `_prevGuestPhase`. Without this, pre-disconnect snapshots either block fresh ones via the out-of-order guard, or the guest lerps across a giant frame gap.
- **PAUSE state in RECONNECT_SYNC**: `ReconnectSyncMessage.paused?` carries the host's `gameLoop.isPaused()` at reclaim time. Guest calls `pause()`/`resume()` in the handler before `completeReconnection()` so it matches the host's suspended sim.
- **Visibility-aware stall detection**: `NetMatch` installs a `visibilitychange` listener in `start()` (removed in `stop()`). When the tab returns, it refreshes `lastSnapshotTime = performance.now()` so the 500ms stall banner doesn't trip spuriously on the first frame back.
- **Room code**: 3 chars from `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (~30k combos). Product decision is short codes for verbal sharing — has flipped back to 4 multiple times during refactors; `transport.test.ts` has a regression pin (`expect(ROOM_CODE_LENGTH).toBe(3)`). DO NOT bump without explicit product sign-off. Length is exported as `ROOM_CODE_LENGTH` from `transport.ts` and imported by `OnlineModal.tsx` for maxLength / submit gating. Updating requires the regex in `transport.test.ts` and the three online E2E helpers (`[A-Z2-9]{3}`).
- **Connection quality HUD**: 3-bar signal icon (top-right, shown on both host and guest). Green/yellow/red based on RTT + jitter thresholds. Wired through `gameLoop.setConnectionQuality()` → `renderer.setConnectionQuality()`. Host calls it in `startHostLoop` after `broadcastSnapshot`; guest calls it in `startGuestLoop`. The `_isNetworkMatch` flag gates rendering (renamed from `_isNetworkGuest` — shown for any network match).
- **`FIXED_TIMESTEP` must be used in NetMatch loops** — never use raw `1/60`. The existing constant is `Math.fround(1/60)` for cross-architecture determinism.
- **cosmeticStep entity removal gotcha**: Carrot/thorn entities are `swapRemove`d by fixedUpdate before cosmeticStep runs. Sounds for these MUST stay inline in fixedUpdate. Use player state transitions (score change, slowTimer change) for guest-side detection.
- **Headbonk must use collision detection, not velocity heuristics** — at jump apex, vy passes through 0 gradually (gravity ~15/tick). Ceiling collision clamps vy to exactly 0. Headbonk stays in fixedUpdate after `collidePlatforms()`.
- **Delta compression (re-enabled in PROTOCOL_VERSION 12)** — auto-enabled on host start (`hostAuthority.enableDeltaCompression(true)` in `NetMatch.start`). Wire format: full = `[0x20, raw bytes]`, delta = `[0x22, baseFrame:u32, curLen:u16, baseLen:u16, XOR+RLE]`. Self-healing protocol: (1) base frame is in the header, guest validates before applying — never produces garbage on baseline mismatch; (2) host keeps last 120 encoded snapshots in a ring, guest does the same; (3) host promotes a peer's baseline only after a SNAPSHOT_ACK lands while the ACKed frame is still in its ring; (4) recovery floor = forced full keyframe every 60 frames OR after 30 frames of ACK silence (`KEYFRAME_INTERVAL` / `STALE_ACK_THRESHOLD` in `core/hostAuthority.ts`); (5) baselines cleared on reconnect (`completeReconnection` calls `guestBaselines.clear()` and host's stop()). **Slow/stressed peers bypass delta**: when a peer is on broadcast divisor > 1 (host's RTT/jitter heuristic OR the guest's own CONNECTION_UNSTABLE signal), `encodeForPeer` returns full snapshots — robustness > the ~50% extra bandwidth saving when CPU/network is already stressed. **Guest auto-signals slow CPU**: when the local `autoSlowDetect` flips, `NetMatch.startGuestLoop` sends one CONNECTION_UNSTABLE so the host bypasses delta to that peer; the guest also stops storing baselines and ACKing (saves ~0.3ms per snapshot on a 4× CPU-throttled guest). Regression suite: `core/hostAuthority.delta.test.ts` (33 tests covering 5%/20%/50% packet loss + 80% ACK loss + reordering + divisor>1 bypass — assertion is **zero corrupted applies** under any combination).
- **Wall-clock interpolation failed** — network jitter makes arrival timestamps noisy, producing jittery lerp factors. Frame-based interpolation (targetFrame = latest - delay) is stable.
- **Touch gesture disambiguation**: `JUMP_COMMIT_DELAY_MS = 80` delays jump reporting to allow swipe-down (crouch) to cancel. `SWIPE_DISTANCE = 25`. Without this, online guests send jump before swipe is recognized.

- **Spawn retry loops must consume a fixed number of `gameRandom()` calls.** `spawnSpring`/`spawnThorn` retry up to `SPAWN_RETRY_ATTEMPTS` times, calling `gameRandom()` per attempt.
